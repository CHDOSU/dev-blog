> 바이브코딩 스터디에서 만든 학습용(비영리) 프로젝트입니다. 저장소: [CHDOSU/youtube-shorts-maker](https://github.com/CHDOSU/youtube-shorts-maker)

## 요약

처음 목표는 "유튜브 링크를 넣으면 세로 쇼츠가 나온다"였습니다.

만들다 보니 무엇을 만들지 고르는 일이 더 어려웠고, 결국 <strong>"구글 트렌드에 뜬 키워드를 짧게 정리해 주는 쇼츠"</strong>로 방향을 틀었습니다.

매일 아침 자동 업로드까지 붙였다가, 마지막에는 쇼츠 한 편 만드는 전 과정을 <strong>Claude 스킬(<code>make-hot-keyword-short</code>)</strong>로 정리했습니다. 이제 "쇼츠 하나 만들어 줘" 한마디면 같은 규칙으로 반복됩니다.

## 1단계: 링크에서 쇼츠까지 파이프라인

처음 만든 구조는 단순했습니다.

```text
유튜브 링크
  │ ① yt-dlp       영상 다운로드 + 채널명/제목 기록
  ▼
  │ ② Whisper      받아쓰기 (문장별 타임스탬프)
  ▼
  │ ③ Claude API   쇼츠로 쓸 30~60초 구간 고르기
  ▼
  │ ④ FFmpeg       자르기 → 9:16 변환 → 자막·출처 새기기
  ▼
short_1.mp4 + 출처가 들어간 설명글
```

| 파일 | 역할 |
| --- | --- |
| `shorts/download.py` | yt-dlp 다운로드 |
| `shorts/transcribe.py` | Whisper 받아쓰기 |
| `shorts/highlight.py` | Claude로 하이라이트 선택 |
| `shorts/render.py` | 세로 영상 + 자막 + 출처 |
| `shorts/upload.py` | YouTube Data API 업로드(OAuth) |

입구는 웹 화면(`app.py`, Flask)과 터미널 실행(`make_short.py`) 두 가지로 만들었습니다. API 키가 없으면 "말이 가장 많은 구간"을 고르는 간단한 방식으로 대체되게 해서, 키 없이도 일단 돌아가게 했습니다.

단계별로 파일을 나눠 둔 덕분에, 나중에 방향을 바꿀 때 ①②④는 거의 그대로 두고 ③만 갈아끼울 수 있었습니다.

## 2단계: "무엇을 자를까"가 진짜 문제였다

인기 급상승 영상에서 하이라이트를 잘라 올려 보니 결과물이 그냥 "남의 영상 일부"였습니다. 볼 이유가 약했죠.

그래서 레퍼런스 쇼츠를 참고해 포맷을 **핫 키워드 해설**로 바꿨습니다.

1. 구글 트렌드 KR 급상승 키워드를 가져옵니다.
2. 그 키워드와 관련된 영상 2~3개를 모읍니다. (최근 14일 이내, 7일 안에 쓴 채널과 3일 안에 쓴 키워드는 제외)
3. Claude가 여러 영상의 받아쓰기를 읽고 하나의 스토리로 이어지는 요약 자막을 씁니다.
4. 3~4개 장면을 문장 경계에서 자르고 오디오 페이드를 넣어 이어 붙입니다.

처음엔 뉴스성 키워드가 많이 잡혀서 너무 딱딱했습니다. 그래서 한 번 더 손봤습니다.

- 주제는 연예/게임/스포츠/밈만 고르고, 뉴스·정치·재난 주제와 뉴스 채널은 제외
- 자막 톤은 호기심을 끄는 훅 + 가벼운 펀치라인
- 장면마다 원본 영상의 좋아요 1위 댓글을 왼쪽 아래 카드로 띄워서 사람들 반응까지 보여 주기

## 3단계: 화면 디자인

- 1080×1920, 위아래 검은 레터박스
- 위쪽 바: 바를 꽉 채우는 훅 한 줄
- 아래쪽: 더 큰 자막을 유튜브 UI(좋아요·댓글 버튼)에 가리지 않게 조금 높게 배치
- 흰색 Pretendard 글꼴
- 내레이션 없음. 대신 자막이 바뀔 때 효과음 + 주황색 강조
- 마지막은 요약 + 질문 한 줄 ("댓글로 의견을 남겨 주세요" 같은 상투어는 빼기)

채널 이름도 포맷에 맞춰 <strong>"지금 뜨는 거"</strong>로 바꾸고 프로필·배너·워터마크를 새로 만들었습니다.

## 4단계: 매일 아침 자동 업로드, 그리고 macOS와의 싸움

`daily.py`로 하루 2편을 만들어 매일 오전 8시에 올리도록 했습니다. 여기서 시간을 가장 많이 썼습니다.

- **cron 대신 launchd**: 맥에서는 launchd(LaunchAgent)로 등록했습니다.
- **셸 스크립트가 막힘**: launchd에서 셸 스크립트를 실행하면 macOS 권한 정책에 막혔습니다. 그래서 launchd가 파이썬을 직접 실행하게 바꿨습니다.
- **바탕화면 폴더 문제**: 프로젝트가 iCloud로 동기화되는 Desktop에 있으니 launchd가 파일을 읽지 못했습니다. 홈 폴더로 옮겨서 해결했습니다.
- **잠자기 문제**: 노트북을 덮어 두면 실행이 안 됩니다. 실행 중에만 `pmset disablesleep`으로 잠들지 않게 처리했습니다. (배터리 상태에서는 예약 기상이 건너뛰어질 수 있다는 한계는 남아 있습니다.)
- **FFmpeg 빌드**: 자막 필터 때문에 `ffmpeg-full` 빌드를 써야 했습니다.

대본 모델로 Claude Opus를 쓰고, 비용은 편당 약 $0.10~0.15 정도입니다.

지금은 자동 업로드를 잠시 꺼 두고, 필요할 때 한 편씩 만드는 방식으로 운영하고 있습니다.

## 5단계: 과정을 Claude 스킬로 만들기

여기까지 오니 쇼츠 한 편을 만들 때 지켜야 할 규칙이 꽤 많아졌습니다. 키워드 필터, 채널 중복 금지, 자막 톤, 레이아웃, 업로드 방식까지요. 매번 설명하기도 번거롭고, 한두 개만 빠져도 결과물이 흔들렸습니다.

그래서 이 과정을 Claude 스킬로 정리했습니다. 스킬이 무엇인지는 [지난 글](/blog/claude-skills-intro/)에서 다뤘는데, 이번에는 실제 프로젝트에 적용해 본 셈입니다. 스킬의 뼈대는 이렇습니다.

```markdown
---
name: make-hot-keyword-short
description: 지금 뜨는 거 채널용 쇼츠 한 편을 만들 때 사용: 구글 트렌드 키워드 선정부터 영상 수집, 자막, 렌더링, 업로드까지.
---

1. 준비            가상환경, ffmpeg-full, 환경 변수 확인
2. 키워드          트렌드 KR 중 연예/게임/스포츠/밈, 3일 내 중복 금지
3. 원본 영상       2~3개, 14일 이내, 7일 내 채널 중복 금지, 인기 댓글 수집
4. 대본/자막       하나의 스토리, 훅 + 펀치라인, 요약 + 질문으로 마무리
5. 렌더링          레터박스, 효과음 + 주황 강조, 댓글 카드, 출처 표기
6. 확인 후 업로드  결과 프레임을 먼저 보여 주고 확인받기
```

마지막 단계에 <strong>"결과 프레임을 먼저 보여 주고 확인받기"</strong>를 넣은 게 포인트입니다. 자동화하더라도 공개 업로드 직전에는 사람이 한 번 보게 했습니다.

이제 "쇼츠 하나 만들어 줘"라고만 하면 Claude가 스킬을 불러와 같은 규칙으로 처음부터 끝까지 진행합니다.

## 회고

- **코드보다 기획이 먼저 바뀝니다.** 기술 파이프라인은 초반에 거의 완성됐고, 이후 시간은 대부분 "어떤 쇼츠가 볼 만한가"를 바꾸는 데 썼습니다.
- **자동화의 적은 OS였습니다.** 로직보다 권한, 잠자기, 동기화 폴더 같은 환경 문제가 더 오래 걸렸습니다.
- **반복되는 지시는 스킬로.** 대화로 쌓인 규칙을 파일 하나로 굳히니, 새 대화에서도 품질이 유지됩니다.

## 저작권에 대해

학습·비영리 목적이며, 모든 쇼츠에 원본 채널명과 링크를 표기합니다. 다만 출처 표기가 저작권 허락을 대신하지는 않습니다. 비슷한 걸 만든다면 Creative Commons 영상이나 직접 찍은 영상으로 시작하기를 권합니다.
